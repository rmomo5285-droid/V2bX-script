## Implemented in the core branch

- Parses XBoard route rules for bare domains, `domain:`, `wildcard:`,
  `regexp:`, and supported protocol rules with validation errors instead of
  silently accepting malformed input.
- Applies XBoard domain and BitTorrent rules to the native Hysteria2 core.
  Unsupported native-Hy2 protocol rules stop that node from starting instead
  of creating a false sense of enforcement.
- Adds destination safety checks and a bounded per-user abuse guard to Xray,
  sing-box, and native Hysteria2 paths.
- Adds rate-limited audit records with user UUID, destination host or IP, port,
  protocol, and block reason. HTTPS full URLs are not visible without TLS
  interception and therefore are not claimed.
- Adds bounded in-memory state and cleanup for abuse and audit tracking.
- Makes native-Hy2 node access concurrency-safe and adds UDP per-packet checks.
- Removes double parsing of geodata, adds a process-wide geodata cache and
  update lock, caps downloads, and uses atomic file replacement.
- Improves certificate domain validation, SAN handling, atomic writes, and
  rollback behavior during reload.
- Fixes native Hysteria2 stream-window assignment, path-MTU setting handling,
  UDP socket cleanup, selector cleanup, user-change detection, and token
  redaction.
- Emits SHA-256 sidecars from the core release workflow.

## Implemented in the deployment branch

- Generates an explicit core/protocol compatibility matrix:
  - Xray: Shadowsocks, VLESS, VMess, Trojan
  - sing-box: Shadowsocks, VLESS, VMess, Hysteria 1/2, Trojan, TUIC, AnyTLS
  - native Hysteria2: Hysteria2 only
- Generates conservative routes for non-public/special destinations, SMTP port
  25, and BitTorrent while keeping the documented public anycast exceptions.
  It does not generate broad QQ, Baidu, bank, Google, Taobao, or political-site
  regex blocks.
- Removes the legacy generated native-Hy2 China ACL only when it exactly
  matches the known upstream pattern. Custom or partial ACLs are refused.
- Adds a transactional migration script that downloads and verifies release
  assets before stopping the old service, backs up installation/configuration,
  switches atomically where possible, health-checks, and can roll back.
- Adds a low-memory systemd guard only for qualifying native-Hy2 nodes.
- Adds conservative BBR/fq, ECN, and RAM-scaled socket tuning with check,
  apply, and rollback modes. It detects later-loading sysctl conflicts.
- Adds bounded logrotate policy and `V2bX userlog [UUID] [minutes]` lookup.
- Adds per-node certificate paths and corrects generated config keys and report
  thresholds.
- Adds shell syntax and regression-test CI.

## Important operational boundaries

- Existing config, all configured cores, all nodes, and custom routing are
  preserved by migration. Missing hardening defaults are added; custom values
  are not intentionally overwritten.
- Network tuning and low-memory guarding are separate transactions. Failure of
  either does not roll back a successfully migrated core, and each has its own
  rollback command.
- Native Hysteria2 and sing-box Hysteria2 are different backends. Native
  Hysteria2 needs the core changes in this branch to enforce XBoard route rules.
- Destination scanning controls reduce abusive fan-out; they are not a complete
  IDS, DDoS appliance, or substitute for provider/firewall egress policy.
- Full HTTP paths may be visible only for plaintext HTTP. HTTPS paths cannot be
  logged by a normal L4 proxy without intercepting TLS.
- The old panel blocklist may contain broad business-policy entries. The core
  enforces panel-supplied rules, but the deployment generator intentionally does
  not recreate those broad rules.
